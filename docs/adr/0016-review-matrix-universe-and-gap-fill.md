# ADR-0016: ③の check ごとに対象種別を定義して母集団を固定し、未チェックのセルは第 2 パスで埋める

- Status: Accepted
- Date: 2026-09-30

## Context

- ADR-0006 は「対象 × 軸のマトリクスで各セルを finding / pass / n.a. のいずれかにし、pass も明示的に出力する」と定めた。「見ていない」と「見て OK」を区別するためである。
- 実際の 2 回の run では、レビュアーは finding を出した対象以外に pass / n.a. をほとんど書かなかった。migration-agent-base では A 軸 231 セル中 199 が未チェック、自己レビューでは A 102 / 121、D 129 / 168、B 80 / 140 が未チェック。C 軸だけが全セルを埋めた。agent 定義の「すべてのセルを埋める」という指示は効いていない。
- 現在のマトリクスの母集団は「その軸のレビュアーが触った対象」であり（run.mjs の merge S4）、レビュアーが触らなかった対象は母集団に入らない。つまり触らなければ未チェックにすら数えられず、網羅性の可視化が自己申告に依存している。
- 軸単位で母集団を「全ファイル」にすると、「フロー × B1」のように定義上あり得ない組み合わせが大量に生じ、レビュアーはそれを n.a. で埋める作業に追われる。check ごとに「どの種類の対象に当てはまるか」は基準文書の時点で決まっている。
- ADR-0005 は①②の網羅性検証を「スクリプト中心」と定めた。③の網羅性（セルが埋まっているか）も、母集団が固定されれば同じくスクリプトで判定できる。

## Decision

- `references/<axis>-*.md` の check 表に **`対象` 列**を足し、check ごとに当てはまる対象種別を書く（A〜E 全軸）。語彙：`file`（全ファイル）、`file:<kind>`（`file:skill`、`file:claude-md`、`file:rule`、`file:agent`、`file:command`、`file:hook-script`、`file:settings` 等、discover の `kind`）、`hook`、`memory`、`mcp`、`flow`、`harness`。複数は ` / ` 区切り。references/README.md の表定義もこの 5 列にする。
- **母集団**：check ごとに、`harness.json` / `flows.json` からその種別の対象をすべて列挙したもの。id は merge S1 の正規化済み id（`./` と末尾 `/` を落とす）を使い、同じ対象が表記違いで 2 セルにならないようにする。`flow:x#n`（step）を対象にした finding はフロー `flow:x` のセルに帰属させる。
- **母集団外の記入**：レビュアーが check の対象種別でない対象に出した finding / pass / na は消さず、セルを作って `in_universe: false` の印を付ける（表示は破線）。findings 本体とマトリクスの不整合を作らない。印の多い check は `対象` 列の見直し材料になる。
- **1 パス目から母集団を渡す**：`plan S3` が軸ごとに `work/review/<axis>.input.json` を書き、check × 母集団のセル一覧（`target` は `{ type, id }`）と check の定義を入れる。reviewer はこの一覧をすべて finding / pass / na で埋める（自分で列挙した対象を足してもよい）。穴埋めパスは、それでも残った分だけを扱う。
- merge S3 は母集団 × check から finding / pass / na の無いセル（**未チェック**）を軸ごとに数え、`work/review/gaps.json` に一覧を書く（`target` は `{ type, id }`）。**未チェックがあり、まだ穴埋めしていなければ exit 3**（`gaps.retry: true`）にして、オーケストレータに穴埋めを機械的に促す。欠落軸・不備 finding の再試行が先で、穴埋めはそれらが片付いてから。欠落軸の再試行は 1 回。それでも欠けた軸は全セルを未チェックとして穴埋めに回す（穴埋め入力の `existing_output` は `null`）。欠落が穴埋めを止めることはない。
- `plan S3 --gaps` は未チェックのある軸ごとに、**40 セルずつ**に分けて `work/review/gaps-<axis>-<n>.input.json`（未チェックのセル一覧と check の説明、既存出力のパス）を書き、batch 一覧を出す。SKILL.md は各 batch の harness-reviewer を**1 回だけ**「穴埋めモード」で起動する：既存の `<axis>.json` は読むだけで、**未チェック分だけを別ファイル `<axis>.gaps-<n>.json` に書く**（`target` はセルのオブジェクトをそのまま）。merge S3 がすべてを連結し、同じ対象 × check は**妥当性検査を通った**既存を優先する（連結分には `source: "gap-fill"`）。重複排除は検査のあとに行い、検査で除外されたセルは穴埋めで埋まる。既存 finding が消えるリスクと、出力を 1 回の Write に載せる上限リスクを避けるため。
- merge S3 の妥当性検査を広げる：`target` が文字列なら `{ type, id }` に正規化する。pass に `note`、na に `reason` が無いものは除外する（穴埋め圧で安易な pass を書かせないための最低限の担保）。`対象` 列の未知トークン（kind のタイポ等）は `warnings` に出す（未知トークンは母集団 0 ＝「全部見た」と同じ表示になるため）。
- S4 のあと、REJECTED しか無いセル（`rejected-only`）は「見た」扱いにせず、未チェックとして数える。埋め直しはしない。
- 穴埋め後の再 merge は不備 finding の再試行予算（`merges`）を消費しない。穴埋め出力に不備があれば再試行せず除外する。`plan S3 --gaps` は run.json に `gap_fill: planned` を記録し、再 merge で `done` にする。2 度目の呼び出しでは batch を出さない（ループ防止）。残った未チェックは検証ログに出すだけで、それ以上は追わない。
- merge S4 のマトリクスも同じ母集団を使う。母集団に無く記入も無い組み合わせはセルを作らず、表示上は「対象外（`·`）」として未チェック（`?`）と区別する。
- `対象` 列が無い check（将来 references に足された行が列を持たない場合）は、従来どおり「レビュアーが触った対象」を母集団にする。
- ADR-0006 の「対象 × 軸のマトリクス」の母集団を check 単位に絞るので、ADR-0006 の Status 行に「母集団は ADR-0016 で明確化」を注記する（ADR-0013 の運用）。

## Consequences

- (+) 「見ていない」が自己申告に依らず機械的に出る。穴埋めパスで大半が埋まり、残った未チェックだけが本当の見落とし候補になる。
- (+) マトリクスから定義上あり得ないセルが消え、読みやすくなる。
- (+) check の適用範囲が基準文書に明文化され、レビュアーへの指示と機械判定が同じ表を見る。
- (−) 1 パス目にセル一覧を渡すので、reviewer の出力が母集団の大きさに比例して長くなる（B 軸で数十〜百数十セル）。1 パス目は軸 1 つ＝reviewer 1 つで分割しない（軸全体を見渡す必要があるため）。出力上限に当たれば JSON ごと壊れ、merge が軸欠落として再試行する。
- (−) 穴埋めパスは残った未チェックの分だけ、40 セルずつ agent が増える。1 パス目が母集団を埋め切れば発生しない。
- (−) 対象種別の割り当ては人の判断で、粗すぎれば無意味なセルが残り、細かすぎれば見落としが母集団から漏れる。references を直せば変えられる。
- (−) 穴埋めモードのレビュアーは「埋める」ことに引かれて pass を安易に付けうる。pass には `note` が必須で、S4 は pass を検証しない（ADR-0005 v1）ので、その品質は検証されない。
- (−) 穴埋め出力の不備 finding は再試行されずに除外される。

## 検証

### 1 回目

- Date: 2026-09-30
- Verifier: adr-verifier
- Verdict: PLAUSIBLE

#### 指摘

1. [事実] Context の数値と「母集団は触った対象」の記述は実データと一致。誤りなし。
2. [事実] `対象` 列が A 軸に無く、未チェックが最も多い A 軸だけ効果を受けない。references/README.md の表定義も 4 列のまま。
3. [結果] 母集団外の finding の扱いが無い。「セルを作らない」だとマトリクスから消え、findings 本体と不整合。実装（`m-extra`）とも食い違う。
4. [結果] 既存 `<axis>.json` を Read して書き直す方式は、既存 finding を落とすリスクと、数百セルを 1 回の Write に載せる上限リスクがある。減少警告は不備のあった軸にしか効かない。
5. [導出] 穴埋め結果を別ファイルに書かせて merge が連結する案が同じ Context から導け、4 の両リスクが消える。
6. [結果] 穴埋め後の再 merge が不備 finding の再試行予算（`merges < 2`）を消費する。
7. [導出] 未チェックを exit 3 にしないと穴埋めの起動が散文指示だけに依存する。Context 自身が散文指示の無効を述べている。
8. [事実] 語彙に `mcp` が無い。`mcp:<name>` 宛ての finding は全 check の母集団外になる。
9. [矛盾] ADR-0006 の適用範囲を狭めるのに、Status 行への注記の指示が無い。

#### 対応

1. 対応不要。
2. A 軸にも `対象` 列を入れた（スクリプトの重複判定が A の別の表の `| 対象 |` に誤反応していた）。references/README.md の表定義を 5 列に直した。
3. Decision に「母集団外の記入はセルを作り `in_universe: false` で印を付ける」を明記した。
4・5. 穴埋め出力を `<axis>.gaps.json` に分け、merge S3 が連結・既存優先で重複排除する方式に変えた。agent 定義の穴埋めモードも「未チェック分だけを書く」に改めた。
6. 穴埋め後の merge は `merges` を増やさないようにし、穴埋め出力の不備は再試行せず除外すると Decision と Consequences に書いた。
7. 未チェックがあり穴埋め未実施なら merge S3 を exit 3（`gaps.retry`）にし、SKILL.md の既存の exit 3 処理に乗せた。順序（欠落 → 不備 → 穴埋め）も書いた。
8. 語彙に `mcp` を追加した。
9. ADR-0006 の Status 行と索引に注記した。

実装中に、母集団を列挙する関数で dangling else（`for … if … ; else if`）により `flow` / `file` 分岐が到達不能になっていたバグを、自己レビュー run の実データ（`flow` の母集団が 0）で発見して修正した。修正後の同 run：母集団 170 セル、未チェック 23（A 19 / D 3 / E 1）、模擬穴埋め後 0。

2〜9 で Decision を変えたので 2 回目の検証にかけた。

### 2 回目

- Date: 2026-09-30
- Verifier: adr-verifier
- Verdict: PLAUSIBLE

#### 指摘

1. [導出] 母集団は S3 起動前に確定しているのに、1 パス目のレビュアーにセル一覧を渡していない。散文指示への依存が穴埋めより手前に残る。
2. [結果] 1 のため、穴埋めのコストは実質毎 run の固定コストになる。
3. [結果] 穴埋めが軸 1 つ＝1 batch 固定で分割しない。未チェック数はファイル数 × check 数で伸び、出力上限に当たる。
4. [結果] `gaps.json` の `target` が文字列で、`review@1` の `{ type, id }` と食い違う。文字列のまま書かれた finding は除外され、pass / na は `harness` に畳まれる。穴埋めは 1 回で不備も再試行しないので失敗が黙って通る。
5. [結果] S4 で REJECTED しか無いセルが「見た」扱いになり、未チェックに数えられない。
6. [結果] `対象` 列の語彙が検証されない。未知トークンは母集団 0 ＝全部見た、と同じ表示になる。（参考）pass の `note` 必須は機械検査されていない。

#### 対応

1. `plan S3` が 1 パス目から check × 母集団のセル一覧を入力ファイルで渡し、reviewer がそれを埋めるようにした。agent 定義と SKILL.md を更新。
2. Consequences を「1 パス目の出力が母集団に比例して長くなる／穴埋めは残った分だけ」に書き直した。
3. 穴埋めを 40 セルずつの batch に分割し、出力ファイルを `<axis>.gaps-<n>.json` にした。merge は複数ファイルを連結する。
4. `gaps.json` と穴埋め入力の `target` を `{ type, id }` にし、agent 定義に「そのままコピー」と書いた。merge は文字列の `target` も正規化する。
5. S4 後の `unchecked_cells` に `rejected-only` を含めるようにした。埋め直しはしない（Decision に明記）。
6. `対象` 列の未知トークンを `warnings` に出す語彙検査を merge に足した。pass の `note` / na の `reason` が空のものを除外する検査も足した。

自己レビュー run で確認：1 パス目の入力に A 34 / B 36 / C 63 / D 24 / E 13 セル、穴埋めは A 19 / D 3 / E 1 が 1 batch ずつ、語彙警告 0、不正 pass / na 0。

1・3・4・5・6 で Decision を変えたが、往復上限（2 回）に達したためユーザーの判断で 3 回目にかけた。

### 3 回目

- Date: 2026-10-01
- Verifier: adr-verifier
- Verdict: PLAUSIBLE

#### 指摘

1. [結果] 既存出力と穴埋め出力の重複排除のキーを妥当性検査の**前**の生エントリから作っているため、不備で除外されたセルは gaps に出るのに穴埋め結果が「既存あり」として捨てられ、永久に未チェックになる。
2. [結果] 穴埋めの条件に「欠落軸なし」が入っているため、再試行しても軸が欠けたままだと全軸の穴埋めが行われない。欠落軸のセルは gaps にも数えられない。
3. [結果] 母集団の id が正規化されておらず、S1 の memory に `memory:docs/adr` と `memory:docs/adr/`（末尾スラッシュ違い）が両方あると、片方が永久に未チェックのセルになる。
4. [事実] schemas.md の gaps.json 例が文字列 `target` のまま（Decision と食い違う）。語彙一覧に `mcp` が無い。

#### 対応

1. 重複排除を妥当性検査の**後**に移した。除外されたセルは穴埋め結果で埋まる（Decision に明記）。
2. 欠落軸の再試行を 1 回に限り、それでも欠けた軸は全セルを未チェックとして穴埋めに回すようにした。穴埋め出力は `<axis>.json` が無くても読む。穴埋め入力の `existing_output` は欠落時 `null`（agent 定義・schemas に明記）。SKILL.md の exit 3 処理を `missing_retry` に合わせた。
3. merge S1 の `normalizeTarget` で末尾 `/` を落とすようにし、母集団の id を正規化済みにすると Decision に書いた。自己レビュー run の memory 重複が消え、D の未チェックが 3 → 2 になった。
4. 例を `{ type, id }` に直し、語彙に `mcp` を足した。

模擬データで確認：(a) 不備 finding のセルを穴埋めで pass にすると、検査で除外されたうえで穴埋めの pass が採用され、未チェック 0。(b) E 軸の出力を消すと 1 回目 merge は `missing_retry: true`、2 回目は `gaps.retry: true` で E の 13 セルが穴埋め batch に入り、穴埋め後の merge で未チェック 0。

1・2・3 で Decision を変えた。往復上限を超えているためユーザーに判断を仰ぎ、反映して確定とした（2026-10-01）。
